## 2. Анализ данных

- В `train.csv` 31 530 пар и 3 042 запроса, примерно 10.4 кандидата на запрос (медиана 10, максимум 19).
- Релевантных пар около 26%, то есть примерно 2.7 релевантных фрагмента на запрос. Так как кандидатов около 10, почти все они попадают в топ-10. Поэтому NDCG@10 в основном измеряет порядок релевантных фрагментов внутри короткого списка, и высокие значения метрики (0.93+) получаются даже у простых моделей.
- Пропуски: `title` около 4.5%, `passage_index` около 4.4%, `article_passage_count` около 6.2%, `article_char_count` около 8.0%.
- Доля релевантных по источникам `ingest_source` почти одинакова (S0 25.9%, S1 26.1%, S2 26.1%, S3 24.7%), то есть сильного сдвига меток между источниками нет. Формат записей при этом может различаться.
- Очистка текстов: удаляются навигационный мусор («Главная › Энциклопедия»), сноски `[N]`, HTML-теги, неразрывные пробелы, лишние кавычки и пробельные символы.
- Пропуски в числовых метаданных не заполняются, бустинг использует их как есть. Добавлены флаги `pi_missing` и `text_missing`.

## 3. Финальный пайплайн

**Валидация.** Фолды строятся по хэшу `query_id` (md5 по модулю 5), поэтому все кандидаты одного запроса попадают в один фолд, а разбиение не зависит от версии библиотек. Одни и те же фолды используются на обоих этапах.

**Этап 1: два cross-encoder (дообучение на train, по 5 фолдам).** Для train берутся OOF-предсказания. Для test берётся среднее предсказаний пяти моделей.

| | bge-reranker-v2-m3 | DiTy/cross-encoder-russian-msmarco (rubert) |
|---|---|---|
| Эпохи | 2 | 3 |
| LR | 2e-5 | 3e-5 |
| max_len | 384 | 384 |
| Запросов в батче / накопление | 2 / 4 | 4 / 2 |
| Gradient checkpointing | да | нет |
| OOF NDCG@10 | 0.9346 | 0.8906 |

Функция потерь: listwise softmax по кандидатам запроса плюс 0.3 · BCE. Батч собирается из целых групп (все кандидаты запроса вместе). Точность вычислений fp16, оптимизатор AdamW, linear schedule с warmup 6%.

**Лексические признаки:** BM25 по тексту и заголовку, пересечение токенов (количество и доля), TF-IDF косинусы (слова и символьные n-граммы) для текста и заголовка, длины, цифры, совпадение заголовка с запросом.

**Признаки внутри запроса:** ранг, z-оценка и отставание от максимума для основных скоров.

**Признаки уровня статьи:** максимум, среднее, разрыв с максимумом и ранг статьи внутри запроса. Также скоры соседних фрагментов (предыдущий и следующий по `passage_index` в той же статье).

**Метаданные:** позиция фрагмента, число кандидатов запроса, источник, частота документа среди запросов.

Итого около 95 признаков.

**Этап 2: ранжирующий бустинг** с ранней остановкой на валидационном фолде. Сравнивались CatBoost YetiRank (3 сида) и LightGBM LambdaRank. Веса бленда подбирались по OOF. Лучшим оказался вес CatBoost 0, поэтому финальный сабмит построен **только на LightGBM LambdaRank** (среднее предсказаний 5 фолдовых моделей).

## 5. Ограничения и замечания

- OOF-оценка слегка оптимистична: ранняя остановка бустингов и выбор веса бленда делались по тем же OOF-данным. Реальный скор на лидерборде может быть немного ниже.
- Разница между CatBoost и LightGBM (около 0.001) лежит в пределах шума.
