# Ранжирование русскоязычных поисковых результатов

## 1. Финальное решение

Двухуровневый пайплайн:

1. **Очистка текста** и лексические признаки (BM25 по тексту и заголовку, TF-IDF по словам и символьным n-граммам, пересечения слов запроса с текстом и заголовком, метаданные статьи, ранги и z-score внутри запроса).
2. **Два дообученных реранкера (cross-encoder), OOF по запросам**:
   - `BAAI/bge-reranker-v2-m3`: полное дообучение, 1 эпоха, 5 фолдов, listwise-лосс по запросу (softmax по кандидатам, несколько положительных) плюс 0.3·BCE, fp16;
   - `Qwen/Qwen3-Reranker-4B`: LoRA (r=16, все линейные слои), bf16, 3 фолда, оценка = logit(yes) − logit(no), тот же лосс.
   Для train используются честные out-of-fold скоры, для test среднее моделей по фолдам.
3. **Признаки уровня статьи** поверх скоров реранкеров: максимум, среднее и ранг статьи внутри запроса, разница с лучшим фрагментом статьи, скоры соседних фрагментов (`passage_index ± 1`), нормировка внутри запроса.
4. **CatBoostRanker (YetiRank)**, CV по запросам, усреднение 3 сидов.

Обучающие данные только из `train.csv`. Внешние датасеты не использовались; предобученные веса моделей загружаются с Hugging Face и дообучаются на train.

## 2. Анализ данных

- В `train.csv` 31 530 пар и 3 042 запроса, примерно 10.4 кандидата на запрос (медиана 10, максимум 19).
- Релевантных пар около 26%, то есть примерно 2.7 релевантных фрагмента на запрос. Так как кандидатов около 10, почти все они попадают в топ-10. Поэтому NDCG@10 в основном измеряет порядок релевантных фрагментов внутри короткого списка, и высокие значения метрики (0.93+) получаются даже у простых моделей.
- Пропуски: `title` около 4.5%, `passage_index` около 4.4%, `article_passage_count` около 6.2%, `article_char_count` около 8.0%.
- Доля релевантных по источникам `ingest_source` почти одинакова (S0 25.9%, S1 26.1%, S2 26.1%, S3 24.7%), то есть сильного сдвига меток между источниками нет. Формат записей при этом может различаться.
- Очистка текстов: удаляются навигационный мусор («Главная › Энциклопедия»), сноски `[N]`, HTML-теги, неразрывные пробелы, лишние кавычки и пробельные символы.
- Пропуски в числовых метаданных не заполняются, бустинг использует их как есть. Добавлены флаги `pi_missing` и `text_missing`.

## 4. Ограничения и замечания

- OOF-оценка слегка оптимистична: ранняя остановка бустингов и выбор веса бленда делались по тем же OOF-данным. Реальный скор на лидерборде может быть немного ниже.
- Разница между CatBoost и LightGBM (около 0.001) лежит в пределах шума.
